## Correctness boundaries

Across all four arms:
- exact France sentinel in C1 and every D32 round;
- all C1 full256-token outputs identical to A1;
- six fixed-continuation token-logprob/top20 probes identical;
- fixed batch of32 real2304-token prompts x32 outputs: all32 IDs,
  token logprobs, top5 and text exactly equal A1;
- P32 first-token vectors stable within each arm; audited P/oracle cache counts0.

However independent D32 HTTP waves are NOT bitwise invariant across rounds,
in BOTH baseline and candidate. Some first divergences are at position0.
Do not infer these are harmless or that arbitrary scheduling is now exact.
Fixed-batch parity isolates the profile change better, but first-divergence
investigation across actual batch composition remains open. This is not the
BF16-CK atomic stage2 path, so that separate issue cannot explain this result
without additional evidence. Full divergence positions are in adjacent JSON.

## Shape-first-use latency finding

Full D32 HTTP waves vary by tens of seconds while decode stays steady.
On B, fixed32 short inputs in one batch API call, max_new1, fresh salts:

- first process measurement13.44s;
- identical repeat about0.68s;
- saved response records are completely identical and both cache counts0.

Files: `/tmp/dsv4_tp8_pd_B_fixed_short{,_repeat}.json` and `.log`.
This rules out a KV-cache hit as the explanation for this pair. It indicates
large shape-first-use/initialization cost, consistent with JIT/module/library
initialization, but the exact component has NOT been profiled/identified.
AIter logs untuned BF16 shapes falling back to Torch GEMM. Reading
`aiter/tuned_gemm.py` confirms this fallback, not that it causes13s latency.
Do not label every independent-wave second-round timing fully warm: varying
admission shapes can encounter new specializations even with fixed request IDs.

Next diagnostic should time a reproducible cold/warm identical shape pair
with CPU/GPU events, distinguishing compilation/loading from GPU critical path.
Do not lock clocks or blame XGMI based on these wall-time gaps.

## Review reconciliation / next optimization

The user's C4 trivial-row proposal is supported by the current source:
`python/sglang/srt/layers/attention/dsv4/indexer.py`,
`_fp8_paged_mqa_logits_kernel`, loads Q/K and executes dot without a per-row
Top512-trivial guard. Mode2/3 Top-K already bypasses scores when live length<=512.
Prioritize a default-off logits-only skip using true c4_seq_lens; preserve
the real lengths passed to Top-K, canonical logical/physical IDs and order,
all compressor/KV updates, and active-row score arithmetic. Validate component
and real P1/P32 TTFT before trimming query producers. This turn did not implement
that kernel change. No need to repeat the now-completed Top-K parallel scan.

Do not assume `TRITON_MHC_PRE_MIX_MAX_BS=4` disables M32 on this path: the
current model predicate bypasses that size limit when A2A is none. The limit
belongs to the conditional Mori experiment. Raising it is not a no-A2A fix.

Keep CK fixed-slot stage2 and vector packed B-fragment work separate from this
native SDOT/MFMA P/D profile. The ~6k BF16-CK M36864 profile remains a distinct
opt-in path with its earlier numerical caveats, not this measurement baseline.
