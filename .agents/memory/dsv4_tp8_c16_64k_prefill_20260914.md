# TP8 C16 large-prefill capacity/performance candidate

Base: `50913c2f24`, original DeepSeek-V4-Flash, original checkpoint precision,
native AR, TP8/EP1, 1,048,576-token logical KV pool, 16 distinct real8K source
code prompts (131,069 input tokens). This is separate from the slower default-off
projection/collective determinism diagnostics; those are OFF in this trial.

## Motivation and scope

The old M36864 ceiling originated in a TP4 OOM experiment. Current TP8 uses
half-width expert shards and has more headroom. AIter's actual CK sorter packs
token IDs into24 bits (not16). The candidate raises the limit only for I256
expert shards, under `SGLANG_DSV4_DEBUG_TP8_CK_64K=1`. The helper and runner
consume the same row limit. TP4/I512 remains capped at36864; defaults and small
prefill/decode selectors are unchanged. Unexpected M above65536 is rejected
by the helper. This is an opt-in experiment, not a default rollout.

## Component result

Only physical GCD4, synthetic BF16 inputs, packed FP4 weights, nonconstant
E8M0 scales, Top-6; same CK/SwiGLU/FP32 stage2 configuration as production.
Compare two stages (32768 + remainder) with one joint stage, including sorting,
weight expansion, stage1/stage2 and final cast. Three ABBA cycles per fixture.

| Routing | M | Two-stage median | Joint median | Time reduction |
| --- | ---: | ---: | ---: | ---: |
| balanced | 65536 | 51.002 ms | 46.630 ms | 8.57% |
| balanced | 65533 | 51.089 ms | 46.680 ms | 8.63% |
| skewed | 65536 | 45.223 ms | 40.379 ms | 10.71% |
| skewed | 65533 | 45.390 ms | 40.341 ms | 11.12% |

Each compared full output is finite and elementwise exact on these fixtures.
Component peak PyTorch allocation is6.40 GiB. This is **not** the full-model
VRAM footprint or proof of arbitrary CK atomic determinism. Three CPU guard
tests passed, including default behavior, TP4 exclusion and no GPU init.

## Completed real-service pilot

The service loaded successfully with chunk/max-prefill65536 and the full1M
KV pool. All eight ranks hit the large CK path. It executes two large prefill
forwards per C16 wave rather than four32768-sized forwards. France answered
Paris. No OOM or scheduler failure occurred; the harness stopped its service.

Warmup:4928.10 input tok/s (excluded). Three warm waves:
5407.09 / 5407.25 / 5315.29, median **5407.09 input tok/s**. This is streaming
batch TTFT throughput, not decode throughput or isolated GPU-forward timing.
Historical C16x8K32768 was approximately5310, but the observed variation is
close to this apparent difference: a fresh-process ABBA is required.

Two separate quality waves used all16 real prompts and128 output tokens.
All32 full prompt-ID echoes matched, cached-token counts were zero, outputs
had the expected lengths; the two sets of completion IDs matched16/16.
Four inspected openings were readable code-review responses. This is not a
whole-model numerical/semantic oracle and does not negate earlier row-placement
drift under a different request composition.
