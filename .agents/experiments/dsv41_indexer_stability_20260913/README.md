# V4.1 cutoff-tie stability evidence

`trace-before.json.gz` and `trace-after.json.gz` retain all compared full-tensor
SHA256 values and sampled numerical errors. They are generated by
`scripts/rocm/compare_dsv41_trace.py` from the bounded rank0 hook files.

The comparison covers three requests, each split2304+256; call0/1 are the
reference request, call2/3 and4/5 are the repeats. Input IDs are identical.
Physical page IDs are deliberately excluded from equality requirements.

The before service uses ordinary torch.topk; the after service uses the stable
V4.1 score/ID ordering helper. No weights or score values were changed. The
hook records every output byte's hash, while `sample_*` errors refer ONLY to
the stored sample rows. Its synchronization affects timing: not a benchmark.

Raw `.pt` traces remain in `/tmp/dsv41-prefixtrace-20260913` and
`/tmp/dsv41-prefixstable-20260913` until the next cleanup/reboot.
